# Engineering source selection

Use external research only when it can change an engineering decision. Start with the local codebase, issues, tests, configuration, and runtime evidence. Then prefer, in order:

1. Official language, framework, runtime, database, or vendor documentation.
2. Standards and primary authorities (for example W3C/WAI, IETF, OWASP).
3. Primary project repositories and release notes.
4. Respected open-source implementations, used as evidence rather than authority.
5. Curated references and general discussion, with uncertainty called out.

Record the source, date or version when relevant, the claim it supports, and conflicts. Treat snippets as illustrations, not contracts. Do not generalize one vendor's convention into a universal rule.

Useful starting authorities include [MDN](https://developer.mozilla.org/), [web.dev](https://web.dev/), [W3C/WAI](https://www.w3.org/WAI/), [OWASP](https://owasp.org/), and official documentation for the technology actually in use.
