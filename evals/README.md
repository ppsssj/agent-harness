# Future evaluations

v0.1 defines no benchmark results or runner. Future evaluations should use repeatable repository fixtures and judge both outcome and process evidence.

| Scenario | Questions |
| --- | --- |
| Debugging | Was the root cause established? Were edits minimal? Is regression protection present and passing? |
| Design | Were appropriate references used? Was `DESIGN.md` respected? Are responsive and accessible states addressed? Were generic patterns justified? |
| Implementation | Was scope respected? Were appropriate tests added? Are unrelated changes absent? Was verification performed? |

Evaluations should retain prompts, starting state, expected invariants, permitted tools, evidence artifacts, and an explicit scoring rubric. Measure uncertainty calibration as well as success; do not treat fluent reports as evidence.
